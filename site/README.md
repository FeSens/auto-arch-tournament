# HWE Bench — site

Static site for [HWE Bench](../README.md), served at hwebench.com.

## Layout

```
site/
├── index.html              Home: the V2 results page (static, see below)
├── v1/                     V1 archive, generated by `python -m tools.site.build`
│   ├── index.html          V1 leaderboard
│   ├── methodology.html    V1 methodology (fitness and the three correctness gates)
│   ├── models.html         Per-model deep dive: every rep, every winning hypothesis
│   └── data.html           Index of raw V1 data files (log.jsonl, agent.log, summary.json)
├── v2.html                 Redirect to the home page (the V2 page's old address)
├── methodology.html        Redirects to v1/ (old V1 addresses)
├── models.html
├── data.html
└── css/
    ├── tokens.css          Design tokens (color / type / spacing)
    ├── reset.css           Modern CSS reset
    ├── style.css           Global styles + components
    └── print.css           Print stylesheet (clean PDF output)
```

The site has no JavaScript beyond the chart tooltips. Fonts load from Google Fonts.

## Build

The home page is generated on the `v2` branch, where the V2 data lives, and
copied here as static HTML:

```sh
# on the v2 branch
python -m tools.site.build_v2 --out site    # writes site/index.html
```

The V1 pages and the redirects are generated from `bench/results.jsonl` and
each V1 rep's `log.jsonl` / `summary.json`:

```sh
python -m tools.site.build                  # writes site/v1/*.html and the redirects
```

Models that are registered but do not yet have all expected result rows are
listed by `SCHEDULED_MODELS` in `tools/site/build.py`. They appear as scheduled
on the leaderboard and models pages, show partial progress as reps land, and
drop out of the scheduled table after all expected reps are present.

A GitHub Action (`.github/workflows/pages.yml`) re-runs `tools.site.build` and
deploys to GitHub Pages on every push to `main` that touches the site
or the bench data. It never touches `site/index.html`.

While a local GPT-5.6 field is running, the publication watcher can rebuild,
commit, and push each rep immediately after its final result row and artifact
directory are written:

```sh
python -m tools.site.watch_publish
```

The watcher publishes only `bench/results.jsonl`, the newly finalized rep
directory, generated leaderboard files, and generated site HTML. It exits after
all scheduled GPT-5.6 reps have finalized and refuses to run when unrelated
changes are staged.

## Design system

See `.design/branding/hwe-bench/`:

- `BRIEF.md` — brand brief
- `strategy/STRATEGY.md` — positioning, voice, messaging
- `identity/IDENTITY.md` + `identity/palettes.json` — color, type, spacing tokens
- `patterns/STYLE.md` — composition rules, layout, tables, print stylesheet
