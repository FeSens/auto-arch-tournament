# V3 items found in V2

Each item names the V2 evidence. None changed a scored V2 result.

## Correctness contract

1. **Formal must see the scored RTL.** Two champions had formal-only branches (Opus 5.5 rep2
   shrank its fetch store from 512 to 2 entries per bank under formal; Sonnet 5.5 rep5 swapped
   its RAM register file for flops). Both pass on the synthesized RTL (amendment 12 step 2),
   but nothing required it. Fix: reject tool-define branches other than RISCV_FORMAL_ALTOPS
   (an RVFI lint step), or require identical parameters across the formal, simulation and
   synthesis builds. (`research/runs/EXP-2026-09-28-v2-main/amendment_12.yaml`, `amendment_12_step2.md`)
2. **Bound the fetch address.** Opus 5.5 rep6's next-fetch predictor (64 entries, 4-bit tags)
   can apply an aliased entry's negative offset to a PC near 0. The wrong-path address sits on
   `io_imemAddr` for a cycle before decode redirects. It shows on 10 of the 15 extended
   kernels and on none of the harness's own programs, and formal has no fetch-bounds
   property. Fix: a fetch-valid signal on the port, or a formal assertion that `io_imemAddr`
   stays in range. (NOTES 2026-10-04, extended suite)

## Scoring rules

3. **Count a failed held-out kernel as zero.** `tools/eval/holdout.py` averages only the
   kernels that validate, so a failure can raise the geomean (Opus rep6's new-15 geomean is
   2,309 under that rule and 1,971 over all 15 correct results). Every scored V2 run
   validated all five, so no V2 score moved.
4. **Synchronous memory port.** Agent cores read memory combinationally, and in the FPGA
   bench their instruction data is a register. Reference cores read one cycle after the
   request, as their native buses require. A synchronous port in the contract makes agent and
   reference numbers directly comparable. (NOTES 2026-10-04, reference cores)
5. **Replace the V1 reference citations.** The `cores/{picorv32,ibex,neorv32,vexriscv}/core.yaml`
   CoreMark/MHz figures are for other configs or other metrics (PicoRV32's 0.516 is DMIPS/MHz;
   Ibex's 0.904 is RV32EC). Use the measured stage 2 figures in
   `research/v2/reference_cores/references.json`.

## Harness robustness

6. **Memory bounds on harness evals.** The 2.8.2 campaign had four kernel OOM events and two
   operator kills ahead of the OOM killer: cosim trace runaways (one `run_cosim.py` grew to
   57 GB in 70 s) and formal evals. None changed a scored outcome. A per-account agent cap does
   not reach these, because harness evals run as the operator. Fix: MemoryMax on the eval scope
   (an OOM there mapped to the gate's failure), `-j` sized to memory, stream-parsed traces (or
   trace ELFs capped far below 50 M cycles), and a cap on concurrent trace processes.
   (NOTES 2026-09-30, 2026-10-01/02, 2026-10-03, 2026-10-04)
7. **Private formal work dirs per slot.** Slots of one run share `formal/riscv-formal/cores/`,
   and one slot deleted a sibling's live self-check dir. Harness evals already moved to a
   private copy. Fix: a work dir under each slot's TMPDIR, or `chmod +t` on the shared
   directory. (NOTES 2026-09-30, 2026-10-03)
8. **Hypothesis copy-back.** `shutil.copy2` raises EPERM on a file the agent account owns.
   Use `shutil.copyfile`, or reject a main-clone hypothesis write up front.
   (NOTES 2026-10-02)

## Prompts

9. **State the sandbox gate's allowed paths verbatim.** The implementation prompt forbids
   helper scripts "outside cores/{target}/", while the gate accepts only `rtl/` and
   `test/test_*.py`. One slot broke on leftover self-check logs. (NOTES, 2.8.2 prompt vs gate)
10. **Say that `formal/riscv-formal/cores/` is shared** while item 7 is not done.

## Experimental design

11. **n per system.** At n = 6 and a run-to-run SD of 0.05 to 0.15 in ln(score), V2 resolves
    gaps of about 20% (three tiers) but not the 6 to 10% gaps within a tier (Opus 5.5 vs
    Sonnet 5.5, GPT-6.1 Sol vs GPT-6 Astra, GPT-5.5 vs Luna). At the observed SDs and point
    ratios, 80% power for a single test at 0.05 needs about 17 runs per system for Opus vs
    Sonnet (1.095) and 30 for Sol vs Astra (1.061); at the first Holm step of a 12-pair family,
    31 and 52. GPT-5.5 vs Luna (0.984) is equal for any practical n. More runs per system, or
    a lower-variance metric, is the lever.
12. **Controls.** Run after the campaign: the no-lessons ablation (amendment 14; the lessons
    made no measurable difference for GPT-6.1 Sol, 1.021 [0.913, 1.140]), the textbook-edit
    baseline (amendment 15 part B; every system passes it by round 1 to 3) and the
    random-mutation control (part A). In V3, run controls interleaved with the systems, and
    run the ablation's control arm at the same time (not four days earlier).
13. **Interleave every system.** Three systems joined mid-campaign under amendment 13 (same
    harness, host and budget, not interleaved with the first three). Pre-register the full
    system list, or interleave added systems with a re-run of an anchor system.
14. **Pre-register the extended suite.** The 15 extra Embench-IoT kernels confirmed the
    ranking (Kendall tau 0.956) only as an exploratory check. Making them part of the held-out
    metric would give twenty kernels instead of five.
15. **Score on a second FPGA.** On an Artix-7 200T (amendment 15 part C) the agents'
    designs gain 1.17x Fmax over the Gowin part against 1.67x for the reference cores, and
    four of the six top-tier separations disappear (Opus vs Sol among them); only the split
    between the top four systems and {GPT-5.5, Luna} holds. Agents tune against one vendor's
    timing report for 15 rounds. Either score on two families (tune on one, report both), or
    state the ranking as specific to the target part. (`research/v2/xfpga/results/analysis.md`)
16. **Check a control's behavior, not only its outcome.** The random-mutation control drew one
    mutation set per run in V1 and in V2's first smoke (no hypothesis id in the implementation
    prompt; the seed dropped for agent accounts), so V1's "0 of 135" was 3 draws. The predicted
    outcome (everything fails formal) hid it. Give each control a smoke check of what it did
    (here: distinct, reproducible mutation records per slot). (amendment 16)
17. **A deep-formal flow that can pass.** At the vendored riscv-formal commit the non-ALTOPS
    DIV and REM specs evaluate unsigned (a conditional with an unsigned arm makes
    `$signed(a) / $signed(b)` unsigned), so `make formal-deep` fails every correct divider;
    MULH-family proofs did not finish in 2 h at depth 20; iterative dividers need a BMC depth
    beyond their latency. Fix the spec (wrap in `$unsigned(...)`), and prove arithmetic per
    unit (equivalence of the design's multiplier/divider against a reference) rather than
    end to end. (NOTES 2026-10-05, `research/v2/deep_formal/`)
18. **Formal with stalls, and fetch bounds.** The gate's formal wrapper ties both ready
    signals to 1, so only cosim exercises stalls, and no formal check bounds the fetch
    address. A fetch-bounds property with free stalls (`research/v2/fetch_bounds/`) finds
    the Opus 5.5 rep6 wrong-path fetch below 0 from reset in 9 cycles.
