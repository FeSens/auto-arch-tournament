## INCIDENT: static agent fails all round >= 2 hypothesis writes

Evidence (measured):
- `bench/static/rep1/log.jsonl`: rounds 1 rows are `regression` (real evals);
  all 42 round >= 2 rows are `broken` with `hypothesis_gen_failed`.
- Source: `tools/agents/static_agent.py:50` `_hyp_id_from_prompt` uses
  `re.search(r"\bhyp-\d{8}-\d{3}-r\d+s\d+\b", prompt)`, a bare leftmost
  match with no anchoring to the "Use exactly this hypothesis ID:" clause.
- Mechanism (same class as the 2026-07-15 random-agent INCIDENT, diary
  2026-07-15): from round 2 the prompt's history section quotes prior-round
  hypothesis ids before the id clause, so the leftmost match returns a stale
  round-1 id; the YAML lands at a path outside the round's whitelist and the
  orchestrator records `hypothesis_gen_failed` for every slot.
- Why burn-in missed it: burn-in exercised the static agent only at N=1
  (single round); the round >= 2 path never executed. The random agent got
  N=2 in burn-in and its instance of the same bug was caught and fixed
  (commits adc127f, ec2743d), but the fix was scoped to random_agent.py and
  static_agent.py duplicates the parse.

Decision: `debug` -> fix as a reviewed task (shared hardened parser for all
mechanical agents), then rerun E1a as static rep2. Rep1 stays in
results.jsonl as the incident datum (never deleted; denominator preserved).

Scope check / how this could fool us: LLM-driven arms (opencode, codex) do
not use regex id parsing (the model reads the prompt); burn-in runs C and D
showed zero hypothesis_gen_failed at N=2. No evidence any published v1 row
is affected (v1 predates the static agent entirely).

Lesson (also in research/lessons.md): prompt-parsing mechanical agents must
share one hardened parser and be burned in at N >= 2; an integration test
should build a real round-2 prompt via hypothesis.py's builder and assert
the parser extracts the allocated id.
