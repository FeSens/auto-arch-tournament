## Finding: agent.log and token totals cover hypothesis agents only (measured)

`collect_agent_logs` only found `.agent*.log` files still on disk at rep
end. Implementer logs live in the slot worktree, which is deleted after
the slot. Scribe logs are deleted by the scribe's own scrub. So the
published `agent.log` and `total_tokens_*` cover only the hypothesis
phase.

Evidence (GPT-6 Sol rep1): the published transcript holds 45 files, all
`.agent.<hyp>.log`. Codex's session store in the kept clone holds 136
sessions (45 implementers, 45 hypothesis agents, 46 scribes) totalling
137,005,804 in / 1,654,470 out, against 32,527,688 / 592,247 in the row
(about 24% of input).

Scope (inferred, not re-measured per row): every published row from this
collector has the same undercount, since the collector is
runtime-independent. That covers token columns, and dollar cost for
opencode rows that report cost from the same logs. Fitness, outcomes and
gates are unaffected. Before any token or cost claim, recount from
runtime session stores where they survive (Codex CODEX_HOME sessions;
opencode storage), or label the columns as hypothesis-phase only.

Fix: `8da0d1e` on `fix/eval-hardening` archives implementer and scribe
transcripts to `.tmp/agent-logs/` before deletion, and the collector
includes them.

## Claude Code isolation (for the Opus 5.5 run)

The harness's claude provider had never been used in production. It ran
`--dangerously-skip-permissions` with the operator's full `~/.claude`:
plugins (superpowers hooks), user settings, auto-memory, and claude.ai
connectors (Gmail, Drive, Calendar). Parity with the Sol treatment was
verified by probes against Claude Code 2.1.282:

- A fresh `CLAUDE_CONFIG_DIR` is logged out (the Keychain entry is keyed
  per config dir). The default login plus `--setting-sources ""`,
  `--strict-mcp-config`, and settings disabling hooks, connectors and
  auto-memory gives an init event with no MCP, no user plugins and no
  memory.
- Bash sandbox (seatbelt):
  - Reads of $HOME, `/private/tmp` and other Claude sessions' temp
    subtrees are denied. The rep's own session temp dirs, the clone, the
    toolchain and riscv-formal stay readable.
  - Writes are confined to the clone.
  - No network.
  - Claude's own `/tmp/claude-<uid>` must stay readable and writable
    (Bash cwd tracking and output capture live there).
- `acceptEdits` in `-p` mode denies file-tool access outside cwd. An
  explicit `Bash` allow is needed, or commands containing `$(...)` are
  refused.
- Disallowed tools: web lookup (as in the Codex runs), plus tools that
  reach outside the rep (SendMessage, ListAgents, PushNotification,
  RemoteTrigger, Cron, ScheduleWakeup, Workflow, DesignSync, worktree
  tools).
- The clone base is outside the repo, because Claude Code loads parent
  directories' CLAUDE.md. The runner refuses a clone with such an
  ancestor.

Known differences from the Codex treatment:
- Claude reads are stricter: Codex could read anywhere.
- `/tmp` writes are denied here, where Codex allowed them.
- Claude session transcripts are written to the operator's
  `~/.claude/projects/` (the default config dir). The agent cannot read
  them.

The first launch's `init` event confirmed: `claude-opus-5-5`, OAuth
(apiKeySource none), acceptEdits, `mcp_servers: []`, only the built-in
`agents-md` plugin, `memory_paths: null`.
